# SWGOLO — Python pipeline

SWGOLO simulates extensive air showers (EAS), reconstructs their properties with a neural network, and optimizes the detector layout.

This script-based version was adapted from the original Jupyter notebook `SWGOLO7`, developed by Ulas, to make the pipeline easier to execute and maintain, particularly on remote machines. A major methodological improvement is the introduction of a **curriculum learning strategy** for neural-network training. The reconstruction tasks are treated separately through dedicated loss terms: shower-core reconstruction, continuous parameter regression (energy and arrival direction), and gamma/proton classification (discrete parameters). Their relative weights are progressively adjusted during training, initially emphasizing shower-core reconstruction and gradually increasing the contribution of the other continuous parameters.

The same curriculum-based approach is also used during periodic fine-tuning of the reconstruction network within the detector-layout optimization procedure. This allows the network to adapt to changes in detector geometry while balancing the different reconstruction tasks.

Preliminary results show improvements in the reconstruction of shower energy, core position, and arrival direction compared with the previous training approach. 

## Pipeline

Run the steps in this order. `functions.py` is imported by the other scripts; it is not run directly.

1. **`functions.py` — configuration and shared functions**  
   Set the directory containing all Python scripts and the shower-parameterization files (`Fit_Photon_10_pars.txt`, `Fit_Proton_2_pars.txt`). This file defines the simulation settings, EAS and detector-response simulation, neural network, label normalization, and layout-optimization utilities.

2. **`inputs_labels.py` — dataset generation**  
   Generates synthetic gamma- and proton-induced showers from the parameterizations. It simulates detector particle counts and arrival times, including background and detector-response smearing, and saves the network inputs and labels. Training and validation samples are generated independently with the same simulation; the validation sample currently contains 10% as many events as the training sample.

3. **`training.py` — network training**  
   Loads the training and validation datasets and trains the reconstruction network. It uses curriculum learning: core reconstruction is emphasized early in training, and the loss weights are progressively adjusted to balance the other targets. This is the main training-strategy change relative to the original notebook. The script saves the trained model (`.pth`) and the training/validation loss plot.

   ```bash
   python training.py \
     --inputs <training_inputs> \
     --inputs_val <validation_inputs> \
     --labels <training_labels> \
     --labels_val <validation_labels> \
     --set_name <run_name>
   ```

4. **`reco_true_plotsv2.py` — reconstruction evaluation**  
   Loads a trained model and tests it on newly simulated showers. It stores true and reconstructed energy, core coordinates, direction, and primary-particle type. It also produces the enabled reconstruction diagnostics, including the energy-resolution plot.

   ```bash
   python reco_true_plotsv2.py --model_path <path_to_model.pth>
   ```

5. **`optimization.py` — detector-layout optimization**  
   Loads a trained model and an initial detector layout (the text files in `Python_Layouts` folder of this repositary can be used). It simulates showers for the current layout, evaluates the reconstruction utility, and updates detector positions. The reconstruction network is periodically fine-tuned using showers generated with the updated layout. The script saves optimization checkpoints, layouts, and utility diagnostics.

   ```bash
   python optimization.py --model_path <path_to_model.pth>
   ```

## Dependencies

The scripts require:

- Python 3.10 or newer
- PyTorch
- NumPy
- Matplotlib
- Pandas

Choose the PyTorch installation that matches the machine and available hardware (CPU or CUDA). Users can create and manage the Python environment with their preferred tool, such as Conda, `venv`, or `pip`.

## Required inputs

- Gamma- and proton-shower parameterization files, with their locations set in `functions.py`.
- Training and validation tensors generated by `inputs_labels.py` before running `training.py`.
- A trained model (`.pth`) and an initial detector-layout file before running `optimization.py`.

Run commands from the project directory and adjust local directory settings in `functions.py` as needed.
